Send a file from screen to phone

1. Prepare the sender

On the sending computer, choose Send files, select your files and tap Prepare transfer. Going offline? Download the browser sender below first, then open that HTML file on the computer.

2. Scan on the phone

Open this hosted page on your phone, choose Receive files and tap Start camera. Allow camera access and keep the entire white QR square in view. On the computer, tap Start sending.

3. Save verified originals

Wait for All bytes verified, then save each file. Completed groups stay in this receiving browser. A separate Back up to NAS action can save verified files to your private NAS backup folder.

Resume a transfer or recover missing groups

Reopen the same receiving browser at the same address and select your saved transfer. Completed groups survive a reload; unfinished groups need scanning again. On the sender, select the exact same files using the same sender format and prepare again.

Use the receiver's Groups still needed list and the sender's Jump to group / Go controls. Group 0 contains the file list. Pause or turn off Auto advance to hold one group. Clearing browser data, private browsing, storage eviction or moving to another device can remove saved progress.

Camera, speed and sender controls

Use this HTTPS page for phone camera access. Keep both screens awake and the receiving page visible. If scanning stalls, use a larger QR, a 256-byte payload or a slower frame rate. Enlarge fills the screen; Floating QR opens a small output window where supported. Keep its source tab open.

Esc / Stop QR stops and blanks the output. Space starts or pauses when focus is outside a control. You can also read saved QR images or a recording. Offline camera support varies by browser.

Start with a small file. At the default 512 bytes and 4 frames per second, 10 MiB of incompressible data takes roughly 3 hours per pass; missed groups take longer. Hundreds of MB can take days. The 8 GiB capacity is not a speed promise.

Planning a 4 GB project

Open Plan a large transfer above the sending controls. GB means one billion bytes; GiB means 1,073,741,824 bytes. Before preparation, compression and reader speed are assumptions. After preparation, the sender estimate uses actual packed group lengths.

At the default settings, one pass of incompressible 4 GB data takes about 46.6 days; 4 GiB takes about 50.1 days. Extra repeats, preparation, final checks and downloads add time. Larger QR payloads and higher frame rates may be harder for a camera to read. Try your actual devices with a small file before committing to a large batch.

Compression affects transmission, but the reader stores the full original bytes. Check browser quota on the receiving device. OPFS export may require another full copy, so a single 4 GiB file can need over 8 GiB of local browser space including overhead. A browser supporting direct streaming export avoids that browser temporary copy, but the final file still needs disk space.

Completed groups are stored in IndexedDB, not on the NAS. Keep progress on this device requests browser persistence; it cannot protect against clearing data, private browsing or all operating-system cleanup. The tool has a verified 500,000,000-byte synthetic decoder/storage test; a full 4 GB camera transfer has not been tested.

File limits, storage and privacy

Send up to 200 uniquely named files or 8 GiB per batch. ZIP folders first. Any file type is copied byte for byte; spreadsheets are not converted. Files are compressed only when that helps, and originals remain in place.

QR scanning and encoding run locally. Files and camera frames do not upload automatically. Checksums detect corruption; visible QR data is not encrypted or authenticated against a malicious sender. Final files are downloaded, never executed by the reader.

Receiving needs local browser storage and may need space for a second download copy. Quotas and large-file support vary by browser. Save completed files separately. NAS uploads happen only through an explicit backup action, using the existing owner sign-in.

Back up phone files to the NAS

For files already on your phone, use NAS backups in the header. Choose files and tap Back up to NAS. This is a network upload, separate from optical QR transfer. Keep the page visible; pause and reselect the same originals to resume.

Each file can be up to 8 GiB. Completed files keep their original names inside dated folders in \\Mungoon\data\Backups\QRTransfer. This page requires the existing owner account. The backup page never deletes backups.
